# Instructions for Claude

This document provides context and guidelines for Claude (AI assistant) when working on this project.

## Project Overview

This is a **wireframe-driven frontend development project** that supports React, Astro, and plain HTML with Tailwind CSS v4. The project uses a structured workflow with custom Claude Code skills to streamline the design-to-implementation process.

## Claude Code Skills Structure

This project uses **custom Claude Code skills** for wireframe-driven development:

- **skills/**: 9 custom commands for the workflow
- **docs/**: Example artifacts (wireframes) that skills reference
- **.claude/**: Claude Code configuration (settings only)
- **CLAUDE.md**: This file - project instructions for Claude
- **README.md**: User-facing documentation

## Technology Stack

- **Framework**: React 18, Astro, or plain HTML (auto-detected or specified)
- **Build Tool**: Vite (React), Astro, or none (HTML)
- **Styling**: Tailwind CSS v4
- **Design Format**: SVG wireframes, Pencil (.pen) design files
- **Asset Format**: WebP (with JPEG fallback), SVG for icons/logos

## Key Concepts

### Audience: Developer-Only Workflows

The current workflows (SVG Wireframe path and Pencil Design path) are designed for **developer-only environments** where Claude handles both design and implementation — no human designer is required. For teams with dedicated designers, a **Figma-based workflow** (e.g., Figma file → code) is planned for a future update.

### Workflow: Pencil Design Path

The workflow uses Pencil (.pen) designs as an intermediate high-fidelity design step between wireframes and code. This path produces better results because it includes AI-generated images, precise visual verification, and a single implementation step that handles responsive design and images together.

1. **Design Phase**: Wireframes are created as SVG files with unique 4-digit IDs (0001, 0002, etc.)
2. **Pencil Setup**: The `.pen` file must be created manually in the Pencil application before Claude can work with it
3. **Pencil Design Phase**: High-fidelity Pencil designs are generated directly from spec.md with AI images
4. **Implementation Phase**: Responsive pages are implemented directly from Pencil designs

```bash
# Workflow
/generate-svg-wireframes              # Optional - for wireframe reference
# [MANUAL] Open Pencil app and create pencil/design.pen
/generate-pencil-frames                # Designs from spec.md, all breakpoints
/generate-pages-from-pencil pencil/design.pen
npm run dev
```

### Workflow: SVG Wireframe Path

A faster prototyping path that skips the Pencil design step, going directly from SVG wireframes to code. Less polished results (placeholder images, theme-approximated colors) but fewer steps.

1. **Design Phase**: Wireframes are created as SVG files with unique 4-digit IDs
2. **Implementation Phase**: Pages are implemented directly from wireframes and spec.md

```bash
# Workflow
/generate-spec docs/requirements.md single
/generate-svg-wireframes
/generate-pages-from-wireframes
npm run dev
```

### Framework Support

**React, Astro, or HTML**: Skills automatically detect the framework or you can specify it explicitly. If no `package.json` or framework dependencies are found, defaults to HTML.

**Key Differences**:

| Feature         | React               | Astro                         | HTML                          |
| --------------- | ------------------- | ----------------------------- | ----------------------------- |
| File extension  | `.tsx`              | `.astro`                      | `.html`                       |
| Output path     | `src/App.tsx`       | `src/pages/{page-name}.astro` | `index.html`                  |
| Class attribute | `className`         | `class`                       | `class`                       |
| Comments        | `{/* comment */}`   | `<!-- comment -->`            | `<!-- comment -->`            |
| Image imports   | `<img src={img} />` | `<img src={img.src} />`       | `<img src="path/img.webp" />` |
| Import location | Top of file         | Frontmatter (`---`)           | N/A (relative paths)          |
| Routing         | Manual/library      | File-based (automatic)        | N/A (static file)             |
| Build tool      | Vite                | Astro                         | None (open in browser)        |
| Tailwind        | `@import`           | `@import`                     | CDN `<script>` tag            |

### Tailwind CSS v4 Configuration

**Important**: React and Astro projects use Tailwind CSS v4, which differs from v3:

- Use `@import "tailwindcss";` in CSS file
- DO NOT create `tailwind.config.js`
- DO NOT create `postcss.config.js`
- DO NOT use `@tailwind base/components/utilities` directives

**HTML projects** use the Tailwind CDN instead:
- Include `<script src="https://cdn.tailwindcss.com"></script>` in the `<head>`
- No build step or CSS file required

## Available Skills

The project has 9 custom Claude Code skills for frontend development (React, Astro, and HTML):

1. **generate-spec**: Generates `spec.md` from a requirements document (markdown) for use by downstream skills (generate-svg-wireframes, generate-pencil-frames). Takes application type (`single` or `multi`) to determine spec format.
2. **generate-svg-wireframes**: Creates SVG wireframe designs from `spec.md` in the project root for multiple breakpoints (defaults to [1024, 768, 375]). Generates responsive wireframes for all specified viewport widths in a single invocation.
3. **generate-pencil-frames**: Generates Pencil (.pen) design frames directly from `spec.md` for specified breakpoints (default [1024, 768, 375]). Reads `spec.md` to resolve Page vs Component types — builds ALL Components as standalone reusable Pencil components first (components-first workflow), then generates Page designs that reference them via component instances. Uses Pencil design guidelines and style guide for visual decisions. Reads `pencil/coverage.md` to skip already-applied designs (incremental design). Updates the coverage manifest after completion.
4. **generate-pencil-images**: Generates or regenerates AI images (WebP) in `pencil/images/` for nodes in the selected Pencil (.pen) design frame
5. **generate-pages-from-pencil**: Implements responsive React, Astro, or HTML pages from Pencil (.pen) design files, copying images from `pencil/images/` to the assets directory
6. **convert-images-into-webp**: Converts PNG and JPEG images to WebP format for optimized file sizes
7. **generate-wireframe-catalog**: Generates comprehensive wireframe catalog documentation
8. **generate-catalog-pdf**: Converts wireframe catalog HTML to PDF, with SVG-to-PNG conversion for reliable rendering
9. **generate-pages-from-wireframes**: Implements responsive React, Astro, or HTML pages directly from SVG wireframes and spec.md, bypassing the Pencil design step. Uses project theme colors instead of wireframe placeholder grays. Faster prototyping path with placeholder images.

## Working with This Project

### When User Asks to Create a Page

1. **Check if wireframe exists**: Look in `docs/wireframes/{NNNN}/`
2. **If no wireframe**: Suggest creating one with `/generate-svg-wireframes`
   - **Ensure `spec.md` exists**: If no `spec.md` exists, suggest generating it with `/generate-spec <path-to-requirements> <single|multi>`
   - **Then run the skill**: `/generate-svg-wireframes`
   - **If user wants only desktop**: Use `/generate-svg-wireframes [1024]`
   - **If user wants desktop + mobile**: Use `/generate-svg-wireframes [1024, 375]`
   - **If user wants all breakpoints in Japanese**: Use `/generate-svg-wireframes [1024, 768, 375] ja`
3. **Follow the Pencil design path** (wireframes are optional reference):
   - Ensure `spec.md` exists and `pencil/design.pen` exists (must be created manually in the Pencil application)
   - `/generate-pencil-frames` (designs from spec.md, all breakpoints)
   - Review and refine designs in Pencil editor
   - `/generate-pages-from-pencil pencil/design.pen`
4. **If user wants to skip Pencil** (faster prototyping):
   - Ensure `spec.md` and wireframes exist in `docs/wireframes/`
   - `/generate-pages-from-wireframes`
   - Note: Less polished results (placeholder images, theme-approximated colors)

**Breakpoint Usage** (optional first argument, defaults to [1024, 768, 375]):

- User says: "Create wireframes" -> Use `/generate-svg-wireframes` (all default breakpoints)
- User says: "Create desktop wireframes only" -> Use `/generate-svg-wireframes [1024]`
- User says: "Create desktop and mobile wireframes" -> Use `/generate-svg-wireframes [1024, 375]`
- User says: "Create wireframes in Japanese" -> Use `/generate-svg-wireframes [1024, 768, 375] ja`

### When User Asks to Create a Pencil Design

1. **Check if `spec.md` exists**: The skill requires `spec.md` to discover Page and Component types and to drive all design decisions. If missing, suggest `/generate-spec` first.
2. **Check if `pencil/design.pen` exists**: The `.pen` file must be created manually in the Pencil application before Claude can work with it. If it does not exist, ask the user to:
   - Open the Pencil application
   - Create a new document and save it as `pencil/design.pen` in the project root
   - Ensure the Pencil MCP server is running and connected
3. **If prerequisites are met**: Use `/generate-pencil-frames`
   - The skill reads `spec.md` to discover all Pages and Components
   - Breakpoints default to [1024, 768, 375] or can be specified as an argument
   - Components are built as reusable Pencil components, then Pages reference them
4. **Output**: High-fidelity design frames for all Pages × all breakpoints in the active `.pen` file

### When User Asks to Implement a Pencil Design as Code

1. **Check if .pen file exists**: Look for `pencil/design.pen` or the specified `.pen` file
2. **If .pen file exists**: Use `/generate-pages-from-pencil pencil/design.pen`
   - Framework will be auto-detected (Astro, React, or HTML)
   - Or specify explicitly: `/generate-pages-from-pencil pencil/design.pen astro`, `/generate-pages-from-pencil pencil/design.pen react`, or `/generate-pages-from-pencil pencil/design.pen html`
3. **Process**: Analyzes desktop and mobile screens in the `.pen` file, extracts images, implements responsive page
4. **Output**: Responsive page with actual images from the design

### When User Asks About Wireframe Catalog or Documentation

1. **Generate/update catalog**: Use `/generate-wireframe-catalog`
3. **When to regenerate**:
   - After creating new wireframes
   - After implementing wireframes
   - When documentation is out of date

### When User Asks to Update Styling

**Mobile-First Approach**:

- Base styles = mobile (no prefix)
- Desktop styles = add breakpoint prefix (md:, lg:, xl:)

**Example**:

```tsx
// Correct: Mobile-first
className = 'px-4 md:px-12 text-xl md:text-2xl'

// Wrong: Desktop-first
className = 'px-12 sm:px-4 text-2xl sm:text-xl'
```

**Responsive Breakpoints**:

- 640px -> `sm:` prefix
- 768px -> `md:` prefix
- 1024px -> `lg:` prefix (default)
- 1280px -> `xl:` prefix
- 1536px -> `2xl:` prefix

### When User Asks to Modify Components

1. **Read the component first**: Always use Read tool before editing
2. **Understand current structure**: Analyze existing code
3. **Preserve responsive design**: Keep mobile-first classes
4. **Maintain color scheme**: Don't change theme colors unless requested
5. **Test suggestions**: Mention testing with `npm run dev`

### Complete Order for New Pages

```bash
# PHASE 0: SPECIFICATION
# ----------------------------------------
0. /generate-spec <path-to-requirements> <single|multi>
   -> Reads: requirements markdown file
   -> Output: spec.md in project root
   -> Why: Translates abstract requirements into structured page specification

# PHASE 1: DESIGN (Optional)
# ----------------------------------------
1. /generate-svg-wireframes [breakpoints] [language]
   -> Reads: spec.md from project root
   -> Output: docs/wireframes/{NNNN}/{breakpoint}/{page-name}-wireframe.svg (for all breakpoints)
   -> Why: Optional wireframe reference; generates responsive wireframes for all specified breakpoints

# PHASE 2: PENCIL SETUP
# ----------------------------------------
2. [MANUAL - User action]
   -> User opens the Pencil application and creates pencil/design.pen
   -> The .pen file format is proprietary and can only be created by the Pencil app
   -> The Pencil MCP server must be running and fully connected

# PHASE 3: PENCIL DESIGN
# ----------------------------------------
3. /generate-pencil-frames [breakpoints] [pen-file-path]
   -> Reads: spec.md (to discover all Pages and their referenced Components, and to drive all design decisions)
   -> Reads: pencil/coverage.md (if exists, to skip already-applied designs)
   -> Uses: Pencil design guidelines and style guide for visual decisions
   -> Output: Standalone reusable Pencil components for all Components, then high-fidelity design frames for all Pages × all breakpoints referencing those components. Updates pencil/coverage.md after completion.
   -> Why: Visual design with generated images before coding; components-first ensures reusability and propagation; coverage manifest enables incremental design
   -> Requires: Steps 0 and 2 complete (step 1 is optional)

# PHASE 4: IMPLEMENTATION
# ----------------------------------------
4. /generate-pages-from-pencil {pen-file-path}
   -> Output: src/pages/{page-name}.astro, src/App.tsx, or index.html (with images)
   -> Why: Implement from high-fidelity Pencil design
   -> Requires: Step 3 complete (or existing .pen file)

# PHASE 4 (Alternative): DIRECT WIREFRAME IMPLEMENTATION
# ----------------------------------------
4b. /generate-pages-from-wireframes [wireframe-ids] [framework] [output-path]
   -> Reads: spec.md, docs/wireframes/ SVGs, project CLAUDE.md/theme, src/index.css
   -> Output: src/App.tsx, src/pages/{page-name}.astro, or index.html (with placeholder images)
   -> Why: Faster shortcut that skips Pencil design step; less visual fidelity
   -> Requires: Steps 0 and 1 complete

# ----------------------------------------
5. npm run dev
   -> Start dev server and test
```

## Wireframe Analysis

When reading wireframe SVGs:

1. **Extract viewBox dimensions**: First line, e.g., `viewBox="0 0 1024 2400"`
2. **Identify sections**: Look for labeled text (HEADER, HERO, FEATURES, etc.)
3. **Note colors**: Extract fill/stroke colors for consistent styling
4. **Understand layout**: Observe rect positions and sizes for spacing
5. **Find placeholders**: Text like "[Image]", "[Pack Image]", "[Logo]"

### Responsive Wireframe Analysis

When reading responsive wireframes:

- Each breakpoint has its own SVG file in `docs/wireframes/{NNNN}/{breakpoint}/`
- Compare across breakpoints to understand layout differences
- **Key differences**: Layout direction, grid columns, typography sizes, spacing

## Asset Management

### Image Import Paths

```tsx
// React/Astro: Relative path from src/ to assets
import logoImage from '../docs/assets/logo.png'

// Wrong: Incorrect relative path
import logoImage from './assets/logo.png'
import logoImage from '/docs/assets/logo.png'
```

```html
<!-- HTML: Relative path from the .html file to assets -->
<img src="assets/images/logo.webp" alt="Logo" />
```

### Loading Strategies

```tsx
// Above-the-fold: No loading attribute (eager by default)
<img src={logoImage} alt="Logo" />

// Below-the-fold: Add lazy loading
<img src={packImage} alt="Pack" loading="lazy" />
```

### Responsive Images

```tsx
// Use object-contain for images that should maintain aspect ratio
<img className="object-contain" />

// Use object-cover for images that should fill container
<img className="object-cover" />
```
