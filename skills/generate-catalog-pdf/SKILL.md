# Generate Catalog PDF

You are a build tools specialist. Your task is to generate a PDF from the wireframe catalog HTML file at `docs/wireframes/catalog/catalog.html`, ensuring all SVG wireframe thumbnails render correctly by converting them to PNG beforehand.

## Instructions

1. **Verify prerequisites**:

   a. Check that `docs/wireframes/catalog/catalog.html` exists. If not, inform the user and suggest running `/generate-wireframe-catalog` first.

   b. Check that `rsvg-convert` is available by running `which rsvg-convert`. If not found, inform the user and suggest installation:
      - macOS: `brew install librsvg`
      - Ubuntu/Debian: `sudo apt-get install librsvg2-bin`

   c. Check that `html-to-pdf.js` exists at the project root.

2. **Collect SVG references from catalog.html**:

   - Read `docs/wireframes/catalog/catalog.html`
   - Extract all `src="..."` attribute values that end with `.svg`
   - These will follow the pattern `../{NNNN}/{breakpoint}/{name}-wireframe.svg` (relative to `docs/wireframes/catalog/`)
   - Build a list of all unique SVG paths to convert

3. **Create the images output directory**:

   - Create `docs/wireframes/catalog/images/` if it does not exist
   - Clean any existing PNG files in this directory to avoid stale files

4. **Convert SVGs to PNGs**:

   For each SVG file referenced in catalog.html:

   a. Resolve the absolute path from the relative `../` reference: `docs/wireframes/{NNNN}/{breakpoint}/{name}-wireframe.svg`
   b. Verify the SVG file exists. If not, log a warning and skip it.
   c. Determine the PNG output path by flattening the directory structure with `--` as separator:
      - `../0001/1024/login-wireframe.svg` → `docs/wireframes/catalog/images/0001--1024--login-wireframe.png`
      - `../0005/375/quiz-wireframe.svg` → `docs/wireframes/catalog/images/0005--375--quiz-wireframe.png`
   d. Convert using `rsvg-convert`:
      ```bash
      rsvg-convert -f png -d 150 -p 150 "{svg-path}" -o "{png-path}"
      ```
      - `-f png`: Output format PNG
      - `-d 150 -p 150`: 150 DPI for crisp rendering in PDF
   e. Confirm the PNG was created successfully

   **Important**: Preserve the original SVG files — do not modify or delete them.

5. **Generate a PDF-ready HTML file**:

   a. Read `docs/wireframes/catalog/catalog.html`
   b. Create a modified copy at `docs/wireframes/catalog/catalog-pdf.html`. Refer to [`examples/catalog-pdf.html`](examples/catalog-pdf.html) for the exact CSS and structure. Apply these changes relative to `catalog.html`:

      **Image path replacement**:
      - Replace all SVG `src` attributes with the corresponding PNG path:
        - `src="../0001/1024/login-wireframe.svg"` → `src="images/0001--1024--login-wireframe.png"`
      - Replace all SVG `href` attributes in `<a>` tags similarly:
        - `href="../0001/1024/login-wireframe.svg"` → `href="images/0001--1024--login-wireframe.png"`

      **CSS overrides for PDF layout** — match the CSS in the example file. Key differences from `catalog.html`:
      - `.wireframe-entry`: adds `break-inside: avoid; page-break-inside: avoid;`
      - `.wireframe-row`: uses `font-size: 0; white-space: nowrap;` (inline-block row instead of flex, which Puppeteer handles poorly)
      - `.wireframe-thumb-wrapper`: uses `display: inline-block; width: 31%; margin-right: 2%; vertical-align: top;`
      - `.wireframe-thumb-wrapper a`: adds `display: block; height: 260px; overflow: hidden;` with border/radius/shadow
      - `.wireframe-thumb`: simplified to `width: 100%; height: auto; display: block;`
      - Hover effects removed (irrelevant in PDF)

   c. Save the modified HTML file

6. **Generate the PDF**:

   Run the html-to-pdf.js script:
   ```bash
   node html-to-pdf.js docs/wireframes/catalog/catalog-pdf.html docs/wireframes/catalog/catalog.pdf
   ```

7. **Output**:
   - Confirm the PDF was generated
   - Report:
     - Number of SVG files converted to PNG
     - Any SVG files that were skipped (with reasons)
     - Output paths:
       - PNG images: `docs/wireframes/catalog/images/`
       - PDF file: `docs/wireframes/catalog/catalog.pdf`
   - Suggest opening the PDF: `open docs/wireframes/catalog/catalog.pdf`

## PNG Naming Convention

SVG relative paths are flattened using `--` as a directory separator (stripping the `../` prefix):

| SVG Reference in HTML | PNG Filename |
| --- | --- |
| `../0001/1024/login-wireframe.svg` | `0001--1024--login-wireframe.png` |
| `../0002/375/dashboard-wireframe.svg` | `0002--375--dashboard-wireframe.png` |
| `../0012/768/navigation-header-wireframe.svg` | `0012--768--navigation-header-wireframe.png` |

This avoids creating nested directories while keeping filenames unique and traceable.

## Edge Cases

### catalog.html not found
If `docs/wireframes/catalog/catalog.html` does not exist:
- Inform the user
- Suggest: "Run `/generate-wireframe-catalog` first to generate the catalog HTML"

### SVG file missing
If a referenced SVG does not exist on disk:
- Log a warning: "Warning: {path} not found, skipping"
- Continue processing remaining SVGs
- The thumbnail will be missing in the PDF (broken image)

### rsvg-convert not installed
If `rsvg-convert` is not available:
- Stop and inform the user
- Provide installation instructions for their platform

### No SVG references found
If catalog.html contains no SVG image references:
- Generate the PDF directly from catalog.html without conversion
- Note that no SVG conversion was needed

## Regeneration

This skill should be run:
- After running `/generate-wireframe-catalog` to update the catalog
- When wireframes are added or modified
- When the PDF needs to be refreshed

The PNG images and PDF are fully regenerated each time. Previous PNG files in `docs/wireframes/catalog/images/` are cleaned before conversion to avoid stale files.

## Dependencies

- `rsvg-convert` (from librsvg) — SVG to PNG conversion
- `puppeteer` (Node.js) — HTML to PDF conversion via `html-to-pdf.js`
